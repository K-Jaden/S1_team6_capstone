# 프로젝트 공통 규칙 (Rules)

1. **언어 규칙 (주석)**: 코드 작성 및 수정 시 모든 주석은 항상 **한국어**로 작성한다.
2. **커밋 메시지 규칙 (Git Commit)**: 커밋 메시지를 작성할 때 목적과 작업 내용을 **한국어**로 간단히 서술한다.
   - 형식: `[타입]: [한국어 작업 내용 요약]`
   - 예시: `feat: 로그인 폼 한국어 번역 추가`, `fix: DB 연결 오류 수정`
3. **네트워크 단절 방지 및 생존 확인 규칙 (Ping-Pong)**: 
   - 빌드, 대규모 리팩토링, 긴 명령 실행 등 **작업 시간이 길게 소요되는 작업**을 수행한 후에는 작업 결과를 한 번에 길게 출력하지 않는다.
   - 결과를 보고하기 전, 반드시 `"작업이 완료되었습니다. 결과를 출력해 드릴까요?"`와 같이 아주 짧게 묻는 절차를 거친다.
   - 사용자가 `"응"`, `"진행해"`, `"결과 보여줘"` 등으로 답변하여 네트워크 연결과 자리 참석이 확인된 직후에만 상세한 결과나 수정된 코드를 출력한다.
4. **Git 브랜치 생성 및 명명 규칙 (Branching Workflow)**:
   - 새로운 기능을 개발하거나 기존 코드를 수정할 때는 반드시 **새로운 브랜치**를 생성하여 작업한다.
   - 브랜치를 생성하기 전, 사용자에게 반드시 브랜치명을 제안하고 **승인(확인)**을 받는 절차를 거친다.
   - 브랜치명은 **반드시 영문 소문자와 하이픈(-)**만 사용하여 작성한다.
   - 브랜치명 규칙 형식: `목적/이름` (예: `feat/login-ui`, `fix/button-bug`)
